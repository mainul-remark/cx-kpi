Form Validation and Security Audit Report

This report is based on a code audit of routes/web.php, related Blade forms, controller validation, FormRequest classes, and model-level validation helpers.

Scope note: this report summarizes code-path review results. It is not a live browser execution report.

Highest Risk

Public debug and maintenance routes exposed without authentication.

Highest Business Risk

Billing approval and adjustment logic lacks strict financial upper bounds.

Highest Functional Risk

Asset update flow contains an early return that breaks intended update behavior.

Prioritized Remediation Plan

Priority 1

Disable Public Debug and Maintenance Routes

Issue: /phpinfo, /optimize-clear, and /has-kv are publicly accessible.

Best solution: remove these routes from production entirely. If temporary access is required, protect them with environment checks, authentication, strict admin authorization, and ideally signed internal-only access.

Why first: this is the clearest direct exposure and should be treated as an emergency hardening task.

Priority 2

Fix Broken Asset Update Flow

Issue: the asset update method returns early before the intended transaction completes.

Best solution: remove the accidental early return and let the full update flow execute, including assignment log sync, planogram history handling, and response formatting.

Why second: this is an active functional defect with data consistency impact.

Priority 3

Enforce Workflow Status Validation Centrally

Issue: VM issue status can be mutated through a route parameter without enum enforcement.

Best solution: validate all status transitions through a dedicated FormRequest or workflow service, with a fixed allowed enum and transition map.

Why: route-driven state mutation bypasses the stronger validation used elsewhere.

Priority 4

Harden Billing Amount Rules

Issue: billing dispute approvals and bill adjustments allow unsafe numeric values.

Best solution:

  • Enforce approved_amount <= original_amount.
  • Enforce approved_amount <= requested_amount if that matches business policy.
  • Enforce final_amount >= 0.
  • Move these validations into dedicated FormRequest classes for billing actions.

Why: this is a revenue, audit, and reconciliation risk.

Priority 5

Validate VM Fix Endpoints Properly

Issue: VM fix assignment, proof upload, and status change endpoints use weak or missing request validation.

Best solution: add explicit request validation for assignee existence, allowed status transitions, proof file type/count/size, and permission enforcement at the controller or policy layer.

Why: these endpoints are currently too trusting of request payloads.

Priority 6

Strengthen KV Slot Validation

Issue: slot_number is required but not validated as integer or bounded by configured slot limits.

Best solution: validate slot_number as a positive integer and compare it against the asset type’s maximum slot count in one place.

Why: current logic checks occupancy, but not full correctness.

Priority 7

Refactor Legacy User and Role Validation

Issue: some user and role validation still lives in model helper methods and only checks integer shape for foreign keys.

Best solution: move all mutation validation into FormRequest classes and enforce exists for role_id.* and resource.*.

Why: it reduces integrity risk and makes authorization and validation more consistent.

Priority 8

Improve Frontend and Backend Rule Consistency

Issue: several UI constraints are only partially mirrored in backend validation, and some forms rely heavily on JavaScript checks.

Best solution: keep backend validation as the source of truth, then mirror the same rules in the UI only for usability.

Why: lower security impact, but useful for supportability and predictable UX.

Best Overall Solution Strategy

1. Centralize Validation

Use dedicated FormRequest classes for every mutating endpoint instead of mixing validation between controllers, models, and ad hoc request checks.

2. Centralize Workflow Rules

Move status transitions into service classes or a workflow layer so route parameters and UI payloads cannot arbitrarily set state.

3. Remove Dangerous Production Utilities

Do not leave debug or maintenance routes exposed. The best protection is removal, not delayed restriction.

4. Add Focused Feature Tests

Create route tests for required fields, bad enum values, invalid foreign keys, duplicate conflicts, unsafe financial values, file uploads, and unauthorized access.

5. Keep Backend as Source of Truth

Frontend checks should improve usability only. Security and business rules must always be enforced server-side.

Recommended Execution Order

  1. Disable public debug and maintenance routes.
  2. Fix the asset update early return.
  3. Patch billing amount validation and bounds.
  4. Patch VM issue status transition validation.
  5. Patch VM fix endpoint validation and authorization.
  6. Patch KV slot number validation.
  7. Refactor legacy user and role validation into FormRequests.
  8. Add regression tests around all critical mutating routes.

Audit Notes

Confirmed strong areas: asset type validation, brand validation, key visual validation, key visual file validation, store validation, asset-to-brand assignment validation, and user store assignment validation are generally in better shape than the legacy endpoints.

Main pattern behind weaker areas: direct controller mutations, route-parameter state changes, and older validation code left in model helpers.
